### Обоснование механизма отмены и выбора задержки debounce

Отмена устаревших запросов реализована через AbortController и debounce в функции searchCountry для устранения гонки
запросов, так
как это лучше в плане утилизации ресурсов клиента:

- ответ с сервера не начинает пересылаться -> не расходуется трафик
- ответ не храниться во временной памяти -> меньше расход RAM

Время ожидания для задержки ввода (debounce) выбран равным 1000мс, чтобы с одной стороны сохранить отзывчивость в
интерфейсе, с другой предотвратить достижение ограничение по rate limit от апи

### Big O для mapCountryResponse (и кэша, если делали бонус) с обоснованием

Сложность O(L), где L - количество языков

### Принципы чистого кода с указанием, где конкретно применены

- SOLID (S - single responsibility): функция debounce только откладывает выполнение, searchCountries только для общения с апи, mapCountryResponse только парсит запрос
- Чистые функции: mapCountryResponse и prepareSearchString не обращаются к DOM, не имеют side effects
- dependency injection: searchCountry принимает notifyResponseChange и notifyError, это позволяет не зависеть от UI
- named errors: объявлен отдельный тип для ошибок запросов HttpError для семантики
